# /strategy-report — 주간 전략 보고서 (전문 애널리스트 양식)

> **⚠ 우선순위 (2026-11-14):** 예약 작업 지시문(옛 문구: "v3 양식", "strategy_tg.md를 직접 써서 보냄")과 이 문서가 다르면 **이 문서가 우선**입니다. ① 5단계 테크노펀더 지면(prep → narr → render → pool)은 절대 빠뜨리지 않습니다. ② 텔레그램은 6단계 `strategy_tf.py tg`가 만든 요약 한 번만 보내고, 직접 쓴 v3 요약은 보내지 않습니다. ③ 관찰 풀의 최종본은 `strategy_tf.py pool`이 씁니다.

역할: 이 세션이 **전략가 → (반론가 = 보조 에이전트, 2026-11-15) → 편집자** 순서로 쓴다. 재료(숫자)는 모두 도구가 만든다(토큰 0). 31일 치 채널 글 원문은 다시 읽지 않는다.

**재료는 세 출처를 함께 본다 (2026-11-10 사용자 요청).** 어느 하나에 치우치면 안 된다.

|---|---|---|---|

## 1. 전략가 — 띔 세우기 (메인 1 · 서브 1~2 · 관찰 0~1)
1. **국면 먼저**: 신호등·20일선·폭(오른/내린)·신고가/신저가·외국인 5일·해외 지표로 `regime`를 쓴다. "지금 추세추종을 해도 되는 장인가"에 숫자로 답하고, 국면이 바뀌는 조건(`what_flips`)을 숫자로 적는다.
2. **띔 후보 추리기**: 재료의 ② 말(업종별 주별 글 수 + `채널 흐름` 말 vs 주가 태그 + `🔥 여러 채널 소식` + 7일 `채널 정리·리포트 정리 헤드라인`) · ③ 이익(7일 섹터 상향/하향, 실적 서프라이즈, `채널 리포트 요약 근거`의 목표가 변경 이유) · ④⑤ 가격·돈(업종 5/20일 수익률, 수급) · 자료실 14일 요약 · 띔 메모에서 **세 축 이상이 같은 방향**인 업종을 고른다. 지난 호 띔은 유지·단계 변경·폐기 중 하나로 반드시 판정한다. 채널 정리 헤드라인에 여러 날 반복해 오르는 주제는 띔 후보로 반드시 검토하고, 들지 않았으면 왜 뺐는지 `risks`나 `watch`에 한 줄 남긴다.
3. **띔마다** 형식의 모든 칸을 채운다: 논지 → 논리 ①~⑤(각 2~4문장, 숫자·출처) → 사고 흐름(확인/가설) → 4검증(점수표 기준 0~2점, `trend`에 주별 숫자) → 밸류에이션(있는 숫자만) → 촉매 일정(달력에서) → 기업 지도 4~8개(역할·노출·포인트·stats·밸류·반대·볼 것·행동) → 무효 신호(숫자 조건) → 실적 반영 시점.
4. **원문 확인 최대 3건**: 띔의 핵심 숫자가 요약에만 있으면 `python3 tools/naver_research.py pdf --cat <company|industry|invest> --nid <nid>`로 원문 글자를 받아 쪽수와 함께 확인하고 `references`에 "1차 · 원문 확인 (p.n)"으로 적는다. 드라이브 문서는 자료실 요약(`data/research/docs/*.json`)의 numbers·checked 칸을 쓴다.
5. **업종 스코어카드** 10~15개: 재료의 업종 목록 전부를 4축 점수표로 채점해 합계 순으로. 띔에 든 업종과 점수가 어긋나면 띔을 고친다(점수가 띔보다 먼저다).
6. **관찰 풀** 20~40종목: 기업 지도 종목을 펼치고, 스코어카드 상위 업종에서 RS 80↑·시총 2천억↑ 종목을 더한다. `setup`은 "셋업 없음 / 베이스 형성 중(n일) / 돌파 대기(기준가 x) / 이탈" 중 하나. 종목마다 `watch_for`(숫자 조건)와 행동(관찰/준비/회피).
   - **v3와 TF 지면 일치 (2026-11-14 사용자 확정)**: 행동 `준비`는 `strategy_tf` 펀더 점수 2/3↑ 종목에만 준다. 펀더 0~1(또는 미확인)이면 기술이 좋아도 `관찰`로 쓰고 이유(분기 영업이익·올해 E)를 한 줄 적는다.
7. **시나리오 3개**(강세·기본·약세): 확률은 대략, 트리거는 숫자, 각 시나리오에서 관찰 풀을 어떻게 다루는지.

## 2. 반론가 — 보조 에이전트가 따로 반박 (2026-11-15 사용자 확정)
같은 대화가 자기 띔을 반박하면 이미 정한 결론에 끌려 반론이 약해집니다. 그래서 반론가는 **Agent 도구로 부르는 보조 에이전트**(subagent_type `general-purpose`, 새 머리로 시작)가 맡습니다. 메인 대화는 결과를 받아 합치기만 합니다.
1. 전략가 초안을 먼저 `data/strategy/draft.json`에 저장합니다(아직 save 하지 않음). 테크노펀더 재료도 먼저 만듭니다: `python3 tools/strategy_tf.py prep`.
2. 보조 에이전트에게 맡기는 글(그대로 쓰고 날짜만 바꿈):
   > 너는 주간 전략 보고서의 반론가다. 저장소 /home/user/stock_team. `data/strategy/draft.json`의 themes(띔)와 `data/strategy/tf/prep_날짜.json`의 board(종목)·matrix(업종)만 읽어라(채널 글 원문은 읽지 마라). 할 일: ① 띔마다 가장 강한 반론 3~5개 — "말만 많고 돈이 안 들어오나", "이미 가격에 반영됐나(고점 대비·컨센 괴리)", "실적 반영이 2027년 이후인가", "여러 채널이 같은 2차 자료를 베꼈나", "펀더 점수가 낮은데 기술만 좋은가"를 점검하고, 반론마다 숫자 1개와 출처(파일·칸)를 붙여라. ② 띔마다 확신도를 낮춰야 하면 몇으로 낮출지와 이유(올리는 제안은 하지 마라). ③ 무효 신호(invalid)가 이미 켜졌거나 가까운 띔. ④ 핵심 후보(펀더 2/3↑+기술 2/3↑)와 리더 업종마다 반대 근거 2개(그중 1개 이상은 이익·추정치·수요 같은 펀더 반론) + 깨지는 조건: invalid_f = 펀더멘털로 가설이 깨지는 조건(숫자 있는 이익·컨센서스 하향·수요·계약 조건, 예 "3Q 영업이익이 추정의 70% 미만", "업종 올해 영업이익 컨센서스 증가율이 1개월 안에 +66%→+40% 아래") · invalid_p = 가격·추세 조건(보조, 짧게) · watch_when = 펀더 조건을 언제 확인할 수 있는지. 추정치 변화는 data/cache/fund/코드.json·_est.json 참고. 업종 강도·20일선 비율만으로 된 조건은 쓰지 마라(2026-11-15 사용자 지적). ⑤ 사전 부검: "4주 뒤 이 보고서가 틀렸다면 가장 그럴듯한 이유" 3줄. 숫자는 파일에 있는 것만 쓰고 지어내지 마라. 매수·매도 권유 문장은 쓰지 마라. 결과는 JSON 하나로만 답하라: {"themes":{"T1":{"against":[...],"conviction_to":n|null,"why":"..."}},"invalid_near":[...],"counter":{"코드 또는 업종명":{"against":["",""],"invalid_f":"","invalid_p":"","watch_when":""}},"premortem":["","",""]}
3. 메인 대화가 합치기:
   - 띔마다 `against`를 보조 결과로 채웁니다(전략가가 쓴 반론과 겹치면 하나로). **3개 미만이면 `save`가 막습니다.**
   - 확신도는 보조 제안대로 **내리기만** 합니다. 받아들이지 않을 때는 이유를 `red_team.rejected`에 적습니다.
   - 초안에 `red_team` 칸을 씁니다: `{"by":"보조 에이전트(general-purpose)","n_against":총 개수,"conviction_changes":[["T2",3,2,"이유"]],"rejected":[],"premortem":[...]}`. **이 칸이 없으면 `save`가 막습니다.**
   - `counter`(핵심 후보·리더 업종 반대 근거)는 5단계 `narr_날짜.json`의 `counter` 칸에 그대로 넣습니다.
   - `agents` 목록의 반론가 줄은 "보조 에이전트 · 반론 n개 · 확신도 조정 m건"으로 씁니다.
4. 보조 에이전트가 실패하면 한 번 더 부르고, 그래도 실패하면 메인 대화가 반론가를 맡되 `red_team.by`에 "메인(보조 실패)"라고 적습니다.
- 가설 성적표: `score` 결과로 지난 호 띔·체크포인트를 맞음/틀림/진행으로 채점하고 숫자를 적습니다. 첫 호면 비웁니다(이건 메인 대화가 합니다).

## 2.5 업종 지식 노트 갱신 (Tier 3, 2026-11-11)
스코어카드 상위 3~5개 업종과 띔에 든 업종마다 `data/research/notes/<업종>.md`를 갱신한다(없으면 새로). 살아 있는 메모라 **덮어쓰지 않고 고친다**: 바뀐 줄만 바꾸고 날짜를 적는다. 형식:
```
# <업종> — 큰 흐름 메모 (마지막 갱신 YYYY-MM-DD)
## 지금 시장이 믿는 서사 (3줄 이내, 출처)
## 핵심 숫자 시계열 (표: 날짜 · 지표 · 값 · 출처) — 최근 8줄만
## 찬성 근거 / 반대 근거 (각 3개, 증권사·날짜)
## 이번 주 바뀐 것 (카드 집계의 새 주장에서)
## 이 서사가 깨지는 조건
```
재료는 `## 네이버 산업·전략 리포트 카드` 집계와 자료실 요약만. 노트 한 장은 1,500자 안팎.

## 3. 편집자 — 1쪽 요약과 저장
1. `summary`: headline 한 문장 → bullets 5~7줄(줄마다 숫자 1~2개·출처) → stance(신호등·권장 노출은 **표시만**·모드) → top_sectors(스코어카드 상위 3~5, 행동) → changes(지난 호 대비).
2. `risks`(이 보고서의 한계: 원문 확인 건수, 시세 시각, light 요약 비중), `method`, `references`, `agents`, `sources` 채움.
3. 초안을 `data/strategy/draft.json`에 쓰고 저장:
```bash
python3 tools/strategy_prep.py save --file data/strategy/draft.json   # 형식 검사 → history 보관 → latest.json → config/watch_pool.toml 갱신(임시, 5단계 strategy_tf.py pool이 최종으로 다시 씀)
python3 tools/strategy_prep.py pool                                   # 관찰 풀 종목 수 확인
```
