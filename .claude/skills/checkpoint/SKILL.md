# /checkpoint — 하루 다섯 번 한 장

**2026-11-19 사용자 확정: 하루 5회 = 07:00 · 10:00 · 12:00 · 15:00 · 18:00.** 예약 지시문에 옛 시각(12:30·18:30)이 남아 있어도 이 문서가 최신이다.
- 텔레그램은 **07·12·18시 회차만** 보낸다. 10·15시는 웹에만 올린다 (`checkpoint.py send`가 슬롯을 보고 알아서 건너뛰므로 순서는 똑같이 실행).
- 채널·리포트 정리는 같은 회차가 이어서 쓴다(7-1). 웹 '소식 › 정리'에서는 체크포인트 아래 '근거' 칸으로 붙는다. 그래서 체크포인트 본문에는 결론만 쓰고, 채널·리포트의 자세한 내용은 정리에 쓴다(같은 내용을 두 번 쓰지 않는다).

텔레그램으로 정기 발송하는 글은 이것뿐이다(2026-11-12 사용자 확정 Q2). 짧고, 결론 먼저, 채점이 있다.
**18시 회차는 마감 리뷰를 겸한다** (2026-11-13 사용자 확정: 마감 리뷰 예약을 없애고 여기로 합침).

## 순서 (저장소 루트)
1. `git pull origin main`
2. `python3 tools/checkpoint.py prep > data/cache/checkpoint_prep.md` 후 Read (07·12시 약 2.5만 자, 18시 약 3.3만 자). 슬롯은 시각으로 자동(07/10/12/15/18), 다르면 `--slot`.
   - 07시: 간밤 미국(해외 칸)·오늘 일정·보유 위험이 중심. 10시: 장 초반(시초가 흐름·수급 방향·강한 업종·내 종목). 12시: 오전 변화. 15시: 오후 변화 + 마감 전 점검(보유 손절가·3R, 감시 목록 장중 돌파, 부록 신호 여부).
   - 18시(마감 리뷰 겸): 오늘 마감 숫자·오늘 중요했던 것·잠정실적·오늘 리포트·감시 목록(16:07)·관찰 풀 기준가 근접·매매 복기·내일 볼 것.
3. JSON을 스크래치에 쓴다:
```json
{"made_at":"YYYY-MM-DD HH:MM","slot":"18","title":"32자 이내 한 줄 결론",
 "market":"코스피 5,290.53 ▼0.98% · 코스닥 699.66 ▲0.45% (네이버 15:30 종가) · 외국인 -5,400억",
 "graded":[{"watch":"지난 체크포인트의 볼 것 원문","result":"맞음|틀림|진행","note":"숫자 한 줄"}],
 "changed":["직전 이후 바뀐 것"],"today":["오늘 시장에서 중요했던 것 (18시 회차만)"],
 "now":["지금 상태 — 탑다운: 매크로 → 국면 → 수급 → 업종 (한 줄에 한 단계)"],
 "mine":["보유·핵심 후보에 주는 뜻 (손절까지 %·핵심 후보 기준가까지 %·매매 복기 숫자)"],
 "watch":["다음 체크포인트까지(18시는 내일) 볼 것 — 날짜·숫자 조건"],
 "sources":"네이버 16:15 마감 · 채널 요약 · 감시 목록 11/12 …"}
```
   - **짧게**: 항목 110자 이내. 칸마다 07·12시는 1~3개, **18시는 1~4개**. 뉴스 나열 금지, 숫자 두 개를 이어 '그래서 무엇'을 말한다.
   - **문장은 "~입니다."로 맺는다** (2026-11-13 사용자 확정, 모든 글 공통). "~다."로 끝내지 않는다.
   - `market`·`today`는 18시 회차에만 쓴다. 07·12시는 비운다.
   - **`now`는 탑다운 순서로 쓴다 (2026-11-14 사용자 확정, 사용자는 테크노펀더멘탈리스트)**: ① 매크로(07시는 간밤 해외·금리·환율, 12·18시는 바뀐 것만) → ② 국면(신호등·분산일 `topdown.regime.dist_days_n`·랠리 시도/팔로스루) → ③ 수급(외국인·기관) → ④ 업종(`topdown.sectors_week`의 리더/모멘텀만/기다림 중 오늘 움직인 곳). 한 줄에 한 단계, 필요 없는 단계는 건너뜀.
   - **`mine`에 핵심 후보 거리를 넣는다**: `topdown.core`(펀더 2/3↑ + 기술 2/3↑)의 기준가까지 %를 짧게(예: "핵심 후보 원익홀딩스 8.7% · 엑시콘 10.4% 남음입니다."). 기준가 3% 안이면 맨 앞에. 펀더 미확인 종목이 기준가에 붙으면 "(펀더 미확인)"을 붙인다.
   - `graded`: 지난 체크포인트(재료 맨 위)의 '볼 것'을 모두 채점. 첫 회면 빈 목록.
   - 보유 종목이 손절가 −3% 안이거나 규칙 알림(3R·20일선)이 있으면 `mine` 첫 줄에 쓴다. 매수·매도는 단정하지 않는다(규칙대로라는 사실만).
4. `python3 tools/checkpoint.py save --file <스크래치>.json` (형식 검사 → `reports/날짜/checkpoint_HHMM.md`)
5. `python3 tools/checkpoint.py send` — 텔레그램 발송(유일하게 허용된 정기 글)
6. **18시 회차만**: 읽은 재료만으로 `data/strategy/memos/YYYY-MM-DD.md`에 스트림 메모 1천 자 안팎을 남긴다(토요일 전략 보고서 재료). 새로 더 읽지 않는다.
```
# YYYY-MM-DD 스트림 메모
- 시장: 지수·외국인 수급·신호등 한 줄
- 스트림: 오늘 강해진/약해진 테마 2~4개 (근거 숫자·출처 한 줄씩, 2차 자료 표시)
- 기업: 스트림 안에서 눈에 띈 기업 3~6개 (실적·목표가·주가 반응 한 줄)
- 새로 나온 것: 처음 보는 키워드·논리 (있으면)
- 반대 신호: 스트림과 어긋난 움직임
```
7. `python3 tools/web_build.py --only channels` → `git add data/checkpoint data/strategy/memos reports && git commit -m "체크포인트 HH:MM" && git push -u origin main` (웹은 푸시하면 자동 배포). 텔레그램이 제시간에 가도록 여기까지를 먼저 끝낸다.
7-1. **채널·리포트 정리도 이 회차에 이어서 쓴다 (2026-11-19 사용자 확정: 2시간 정리 예약 5회를 없애고 체크포인트 회차에 합침, 같은 날 5회로 늘림).** `.claude/skills/live-brief/SKILL.md`의 2~8단계를 그대로 한다(`live_brief.py prep` 재료 → 채널 정리·리포트 정리 저장 → 커밋·푸시). 새 글이 없으면(channels_new·report_new 모두 0) 건너뛴다. 정리는 텔레그램으로 보내지 않는다. 예약 지시문의 "checkpoint.py prep 재료만 본다"는 지난 실행 내용을 다시 읽지 말라는 뜻이며, 이 단계의 `live_brief.py prep` 재료는 읽는다(예약 지시문보다 이 문서가 최신).
8. 실패하면 실패 단계·오류(키 값 없이)를 `python3 tools/telegram_send.py "체크포인트 실패: …"`로.

## 지키는 선
- 숫자마다 출처·시각은 `sources` 한 줄로 모은다(웹이 문장마다 줄을 바꿔 괄호가 떨어짐). 채널 글은 2차 자료.
- 지난 실행 내용을 다시 읽지 않는다. 재료 파일만 본다.
- 매매 규칙은 2027-01-31까지 고정. 행동은 준비·관찰·회피.
