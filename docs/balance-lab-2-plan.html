한 장 요약

기능은 이미 많습니다. 문제는 기능끼리 흩어져 있고, 같은 정보가 여러 곳에서 다른 시각으로 보인다는 점입니다. 2.0은 기능을 더하기보다 묶고, 줄이고, 시각을 맞추는 개편입니다.

문제 ① 흩어진 판단

Claude 의견이 인사이트·아침 브리핑·채널 정리·리포트 정리·마감 리뷰에 각각 따로 있습니다. 첫 화면에서 "오늘 결론"이 하나로 모이지 않습니다.

문제 ② 종목 정보가 다섯 군데

한 종목을 보려면 기업 탭·관찰 풀·감시 목록·리포트 흐름·채널 원문을 오가야 합니다. 검색은 이번 주에야 생겼습니다.

문제 ③ 두 개의 화면, 어긋난 시각

Artifact와 웹이 따로 갱신되고, 데이터 시각·브리핑 시각·장중 가격 시각이 서로 다릅니다. 이번 주 고친 오류 6건 중 4건이 여기서 나왔습니다.

2.0의 세 가지 방향

A. 상황판 첫 화면

첫 화면 = 상태 5줄 + 오늘의 결론 1개 + 할 일 체크리스트. 나머지는 접습니다. 하루 세 번의 체크포인트(07:00 · 12:30 · 18:30)에 맞춰 내용이 바뀝니다.

B. 종목 허브

'종목'을 여섯 번째 메뉴로 올립니다. 검색 → 종목 페이지 하나에 가격·RS·셋업·리포트·채널·공시·내 매매가 모입니다. 어디서 종목을 눌러도 여기로 옵니다.

C. 한 줄기 데이터

웹(Cloudflare)으로 일원화하고 Artifact 갱신을 끕니다. 모든 숫자에 '기준 시각' 배지를 붙이고, 장중 가격은 20분 스냅샷으로 따로 갱신합니다.

기대 효과. 하루 확인 시간 30분 → 10분, Claude 토큰 약 20% 감소(Artifact·Haiku 웹 갱신 폐지), 시각 불일치 오류 0건, 종목 하나 보는 데 클릭 5회 → 1회.

PRD — 제품 요구사항

2.1 제품 한 줄 정의

Balance Lab은 장중에 화면을 볼 수 없는 회사원이 텔레그램 채널과 증권사 리포트의 흐름을 놓치지 않고, 고정된 추세추종 규칙대로 "볼 종목 · 기다릴 종목 · 피할 종목"을 하루 세 번 정리받는 개인 상황판이다. 주문은 하지 않는다.

2.2 사용자

주 사용자: 회사원 추세추종 트레이더 (본인)

  • 장중 확인 가능 시간: 출근 전 · 점심 · 퇴근 후, 각 5~10분
  • 전략: 깡토 돌파(셋업 → 기준가 돌파 + 인더스트리 액션), 1R = 30만 원, 처음 손절 −8%
  • 주 사용 기기: 휴대폰(이동 중) 60% · PC(저녁) 40% (추정, 확인 필요)
  • 코딩 초보, 화면은 한국어, 설정은 Claude에게 말로 요청

보조 사용자: Claude 에이전트들

  • Sonnet 데스크(정리·브리핑), Opus 전략 데스크(주간), Haiku(스크립트)
  • 화면을 직접 보지 않고 같은 데이터 파일(JSON)을 읽고 씀
  • 요구: 재료는 짧게, 형식은 고정, 저장 때 자동 검사

2.5 범위

포함 (In)

  • 첫 화면 상황판 개편, 체크포인트 3회 글
  • 종목 허브(검색 + 종목 페이지), 모든 종목 이름에서 연결
  • 웹 일원화, 기준 시각 배지, 장중 가격 20분 스냅샷
  • 결정 로그(매수 때 띔·가설·무효 조건), 띔별 성적
  • 알림 센터(화면 안에서 오늘 보낸 알림 모아 보기)
  • 모바일 우선 레이아웃 정리, 용어 툴팁

제외 (Out)

  • 주문·자동매매 기능 (절대 규칙 1)
  • 매매 규칙 변경 (2027-01-31까지 고정, 표시만)
  • 실시간 체결가 스트리밍 (네이버 비공식·클라우드 제약)
  • 여러 사용자·공유 기능
  • 증권사 리포트 PDF 원본 보관 (절대 규칙 3)

2.6 설계 원칙

  1. 결론 먼저, 근거는 한 번 더 누르면. 모든 화면 맨 위는 한 문장 결론. 근거·원문은 펼치기.
  2. 한 정보는 한 곳에만. 다른 곳에서는 그곳으로 가는 링크만 둔다.
  3. 모든 숫자에 출처와 기준 시각. 화면 단위가 아니라 숫자 묶음 단위로 표시.
  4. 행동은 준비·관찰·회피 세 가지. 매수·매도 단어를 쓰지 않는다.
  5. 휴대폰 390px에서 먼저 설계하고 PC는 넓혀서 같은 순서로.
