# 전략 검토: 추세추종 돌파매매 → 필요한 에이전트 (초안, 2026-10-31)

출처: 사용자가 준 전자책 Chapter 04 "추세추종 트레이딩"(p.240~280). 원문 파일은 저작권 때문에 저장소에 넣지 않고, 아래에는 규칙 요약만 적는다.
**이 시스템은 신호와 알림만 만든다. 주문은 사용자가 직접 한다 (CLAUDE.md 절대 규칙 1).**

## 1. 전략 뼈대 (숫자로 바꿀 수 있는 규칙)
| 단계 | 책의 규칙 | 기계로 판정 가능? |
|---|---|---|
| 종목 풀 | 성장주(매출·영업이익·순이익 균형 성장), 테마주·잡주 제외 | 실적은 가능(DART), 테마 여부는 사람 판단 + 보조 |
| 상대강도 RS | 시장 전체 종목 중 백분위 70 이상. 12M 20% / 6M 30% / 3M 50% 가중 | 가능 — **전 종목 시세 필요** |
| 수급 | 외국인+투신+연기금 중심, 기관 매수가 당일 거래량의 10% 이상 | 가능 — **투신·연기금 세부 데이터 필요** |
| 섹터 | 섹터 동반 상승, 섹터 ETF 20일선 위/아래 | 가능 — 종목↔섹터 표 필요 |
| 추세 | 주봉·일봉 모두 정배열, 52주(역사적) 신고가 근처, ADX 20 이상 & +DI > -DI | 가능 |
| 1stage | 상승률 50~60% 이상(기준), HTF = 8주 안에 +100%, 조정 5일~3주·20% 이내 | 가능 |
| 2stage(조정) | 1stage 상승분의 50% 이상 반납 안 함, 조정 길수록 좋음, VCP(조정폭·거래량 감소), 컵(7~65주, 깊이 12~33%) + 손잡이 | 대부분 가능, 매물대 박스는 거래량 분포로 근사 |
| 매수(3stage) | 매물대 돌파 + 큰 거래량 + 장대양봉(갭 포함), 돌파 1~2% 전 알림, 분할 매수 | 신호·알림 가격 계산 가능 (매수는 사용자) |
| 손절 | -1R (예: 1R = 7%) | 가능 |
| 익절 | 3R에서 50% 매도, 그 뒤 손절선을 본전으로. 2R 또는 +18~19%에서 본전 손절로 올리기 | 가능 (사용자가 입력한 매수가 기준) |
| 추세 꺾임 | 급등주 5일선, 추세주 20일선, 완만한 종목 50·60일선 이탈 + 역배열 + 섹터 ETF 20일선 이탈 | 가능, 최종 판단은 "종합적" → 사람 |
| 클라이맥스 | 신고가에서 역대급 거래량 + 윗꼬리 음봉 → 전량 매도, 고점 -10% 장대음봉, ATR 크기 음봉 3연속 → 비중 축소 | 가능 |
| 불타기 | 1차 30~50% / 2차 15~20% / 3차 10%, 3~5회. 계기: 1R 도달, 1/2·1 ATR 이동, 신고가, 추가 셋업. 3R은 최초 매수가 기준. 물타기 금지 | 가능 (경고·계산만) |
| 목표 통계 | 승률 30% 정도라도 손익비 1:3 유지 | 백테스트로 확인 |

## 2. 필요한 에이전트 (안)
| # | 에이전트 | 하는 일 | 주기 | 데이터 상태 |
|---|---|---|---|---|
| A | 시장 국면 | 지수 방향, 정배열 여부, 돌파 성공/실패 비율 | 매일 장마감 | 지수 있음 (`naver_quote.py index`) |
| B | 스크리너 (종목 풀) | 전 종목 RS 백분위, 52주 신고가, 정배열, 1stage 상승률, 시총·거래대금 필터 | 매일 장마감 | **전 종목 일봉 없음 → 새 데이터 필요** |
| C | 펀더멘털 | 분기 매출·영업이익·순이익 YoY, 추정치 변화, 리포트 요약 | 실적 시즌 + 주 1회 | DART `fin` 미확인, 채널 리포트 있음 |
| D | 수급 | 외국인·투신·연기금 연속 매수, 기관 순매수 ÷ 거래량 ≥ 10% | 매일 | **네이버는 '기관 합계'만 → 세부 필요** |
| E | 섹터 | 섹터별 강도, 섹터 ETF 20일선, 동반 상승 | 매일 | 섹터 표·ETF 목록 필요 |
| F | 셋업 탐지 | 2stage 조정 깊이·기간, VCP, 컵·손잡이, HTF, 매물대 박스 → 돌파 기준가·알림가·1R | 매일 장마감 | 일봉 있음 |
| G | 돌파 확인 | 다음 날 돌파 성공 여부(거래량·종가 유지·윗꼬리) | 장마감 | 일봉 있음 |
| H | 포지션 관리 | 사용자가 적은 매수 기록 기준 R 단계, 3R·본전 손절, 이평선 이탈, 클라이맥스, 불타기 계기, 물타기 경고 | 매일 장마감 | 매수 기록 파일 필요(사용자 입력) |
| I | 검증 | 반대 근거, 숫자 대조, 오래된 데이터 점검 (이미 브리핑에 있음) | 매번 | 있음 |
| J | 백테스트 | 규칙을 과거 데이터로 돌려 승률·손익비 확인 | 규칙 확정 후 | 전 종목 일봉 필요 |

장중 실시간 감시(돌파 1~2% 전 알림)는 클라우드 예약 작업이 시간 단위라 맞지 않는다.
→ 저녁에 **"내일 알림 걸어둘 가격 목록"**을 텔레그램으로 보내고, 사용자가 증권사 앱에 가격 알림을 거는 방식이 현실적이다.

## 3. 데이터 빈칸 (다음 세션 우선순위)
1. **전 종목 일봉** (RS 백분위·스크리너·백테스트): 후보 ① KRX Open API(공식, 키 필요 — `KRX_API_KEY` 이름으로 등록) ② pykrx / FinanceDataReader(비공식) → 클라우드에서 되는지 시험
2. **투신·연기금 세부 수급**: 후보 ① KRX 정보데이터시스템 ② 토스 투자자별 매매동향(기관 세부 있음, 내 컴퓨터에서만) ③ KIS(내 컴퓨터에서만)
3. **섹터 분류**: KRX 업종 분류 또는 직접 만든 표(`config/sectors.toml`)
4. **매수 기록 파일**: `config/positions.toml` (사용자가 매수일·가격·수량·1R% 입력. 주문 기능 아님)

## 4. 사용자에게 정해 달라고 할 숫자
- 1R은 몇 %? (책 예시 7%, 피라미딩 예시 10%)
- RS 기간 계산: 거래일 기준 250/125/63일로 할지
- 정배열 이평선 조합: 일봉 5·20·60·120? 주봉 10·30·40주?
- "1stage 상승률" 측정 구간: 최근 저점에서 1stage 고점까지?
- 조정 기간 최소 길이, 시총·거래대금 하한
- 테마주 제외 기준 (자동 제외 목록을 둘지, 사람이 표시할지)
- 시장 국면 판단 규칙 (책 앞 장에 있다면 그 장도 받기)

## 5. 에이전트끼리 소통 ("bus")
- Claude Code에 "bus"라는 공식 기능은 없다. 비슷한 것: 서브에이전트(결과를 팀장에게만 보고), **에이전트 팀**(실험 기능, 팀원끼리 메시지·공유 작업 목록), 외부 MCP 메시지 버스 프로젝트들(claude-bus, agent-bus 등 — 대부분 초기 단계).
- 이 프로젝트 추천: **파일 게시판 방식** `data/bus/YYYY-MM-DD/에이전트.json`
  - 각 에이전트는 자기 결과를 JSON으로 게시하고, 다음 에이전트는 필요한 게시물만 읽는다 (B→C·D·E→F→I→텔레그램).
  - 장점: 기록이 남아 나중에 "왜 이 신호가 나왔나" 추적·백테스트 비교 가능, 실험 기능에 의존 안 함, 비용 적음.
  - 이벤트 예: `breakout_candidate`(F), `breakout_confirmed`(G), `climax_warning`(H), `stop_hit`(H), `pyramid_trigger`(H), `veto`(I가 반대 근거로 보류 표시).

## 6. 제미나이 활용
- 확인한 사실(2026-10-31, Google 문서): Google AI Pro 구독은 **Gemini 앱·AI Studio 웹 화면의 한도를 올려 줄 뿐, API(프로그램이 부르는 것) 사용량은 별도 과금**. 조건이 맞으면 Google Developer Program에서 월 Cloud 크레딧을 받을 수 있음. Gemini CLI는 2026-06-18 Antigravity CLI로 바뀜.
- 쓰는 방법 후보:
  1. **API 키로 자동화** (`GEMINI_API_KEY` 환경 변수로 등록 — 키 값은 채팅에 붙여넣지 않음): 검증 에이전트의 "두 번째 의견"(다른 회사 모델이 같은 자료로 반대 근거를 찾게 함), 구글 검색 근거가 붙은 뉴스 확인. 무료 등급 + 구독 크레딧 안에서 쓰도록 호출 수 제한.
  2. **사람이 직접 쓰는 곳**: Gemini 앱 Deep Research(섹터 공부), NotebookLM(리포트·책 장들을 넣고 질문). 2stage 조정 기간에 "섹터 리포트 읽고 펀더멘털 파악"하는 일에 잘 맞음.
  3. 내 컴퓨터에서 Antigravity CLI(구독 계정 로그인)로 쓰기 — 클라우드 세션에서는 로그인 방식이 맞지 않을 수 있어 확인 필요.
- 주의: 제미나이에 보내는 것은 공개 데이터와 분석 결과만. API 키·토큰·계좌 정보는 보내지 않는다.
